# Reflection 
This assignment really gave me an insight on how GitHub can be used to organize and manage a software/coding project instead of being just a place to store code, especially as we will be using GitHub for our project in this course. Before this, I thought of GitHub as like a Google Docs type of platform but for coding, but there are more features to it that make it more than that. For example, I learned how to create repositories, use Issues to break the project down into smaller tasks that can be completed, create branches to work on different parts of the project, use commits to keep track of the changes made, and using pull requests to merge the work back into the main branch to compile all the new work together. 
At first, it was a bit confusing to understand how all of these things worked together as there are a lot of features to really work with on GitHub, especially the purpose of branches and pull reuests, but it became much easier to understand once I actually worked on this myself. I like the efficiency and convenience that comes with using GitHub where you can create a simple project based on anything, in this case an idea related to NASA, while practicing on GitHub's central features.
If I had more time, I would lean toward improving the application for this project by adding more features like task priorities, deadlines, and saving tasks, so they don't disappear when the page is refreshed. I found GitHub mostly fun to work with as it was pretty straightforward to understand the basic workflow an how project planning on this platform can make processes more organized.
